# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

TFT Comp Tracker: a static, no-build web app for Teamfight Tactics. The user looks up a live game (or types player names), then links each of the 8 players to the meta compositions they appear to be playing on a "scout sheet": a matrix of comps (rows) × players (columns). There is no package.json, bundler, linter, or test suite.

## Running

Serve the repo root over HTTP (ES modules and `fetch('Data/MetaSnapshot.json')` don't work from `file://`), e.g. `python -m http.server 8000` and open `http://localhost:8000`. `index.html` uses absolute `/favicon.ico`, so the root must be the site root.

## Architecture

- **Entry points** (both `type="module"` in `index.html`): `Scripts/mainScreen/domContentLoad.js` (DOMContentLoaded wiring: region selector remembered in `localStorage`, player search and the `/` shortcut, Solo/Double Up switch, reset, copy names) and `Scripts/mainScreen.js` (startup: `initViewTabs()`, `applyQueryParams()` → `tryLoadDefaultData()`).
- **Modules query the DOM at import time** (e.g. `document.getElementById('players')` in `players.js`, `'compos'` in `dataLoader.js`/`matrix.js`, `'itemPicker'` in `itemPicker.js`), so they rely on `index.html` script placement and there are circular imports between `players.js`, `matrix.js`, `dataLoader.js`, `compSearchBar.js`, `itemPicker.js` and `shareUrl.js`. Be careful when moving code between these files.
- **Shared state** lives in module-level exports rather than a store: `links` (`{compo, player, pivot}` in `matrix.js`; `pivot` is derived on every render: a player on one comp plays it as main, on several every one is a pivot) is the source of truth for the matrix cells, comp states and share URLs, and `renderLinks()` repaints everything derived from it (then fires `tft:linkschange`); `duelsCache` in `players.js`; `metaSnapshotData`, `unitImageMap`, `unitCostMap`, `items` in `dataLoader.js`.
- **Two data sources:**
  1. `Data/MetaSnapshot.json` — one entry per set, keyed by set name (`"SET 18"`): `comps` (TFT Flow's comps and tier list: Default → S, Meta → A, Other → B/C/X; carries are the board units TFT Flow itemizes, their `items` are the ideal build from MetaTFT and their `artifacts` the ones TFT Flow's builds give them; `url` is the TFT Flow guide), `champions` (every 1-5 cost unit from CommunityDragon with `traits`, `stats`, a derived `role` like "Attack Marksman" / "Magic Tank" (tank when defensive components fill half its items, damage type from AD vs AP components, marksman/caster when ranged), `items: {base, games, core, S, A}` rows `[itemApiName, avgPlacement, games]` from MetaTFT live data, `variants: {AD, AP}` tiers for `Adaptor`-style champions, and `holds`: the artifacts/emblems/radiants TFT Flow gives it, with their best tier), `conditions` (TFT Flow's curated lists: `{apiName: {type: artifact|emblem|radiant, name, comps: [{comp: index, tier: S-D, holder: apiName|null}]}}`), `items` (catalog by category: default, artifact, emblem, radiant, trait), `components`, `recipes`, `patch` (MetaTFT patch, or "PBE"), `status` (`live`/`pbe`), `source`/`itemsSource`, `lastUpdated`. A set on the PBE (about two weeks before launch) is published next to the live one with stand-in tiers from TFT Flow builds (`avg` null, `games` = number of builds). Loaded by `dataLoader.js`, cached in `sessionStorage` under a versioned key (`metaSnapshot:v4`; bump it when the format changes, and hard-reload/new tab after changing the file). The live set is the default (older frontends use the last key, so the backend writes the live set last); the set dropdown is built from the keys, labels PBE sets and is hidden when there is only one set, and `getCurrentSetData()` plus the `tft:setchange` document event expose the selected set to other views.
  2. The external **TFT Versus** backend (`https://tft-versus.onrender.com/api`, endpoints in `Scripts/config.js`), called only through `fetchFromTFTVersusAPI` in `Scripts/tftVersusHandler.js`. Errors come back as `{detail, status}` (real HTTP status attached); callers such as `searchCurrentGame.js` check `detail`/`status` rather than catching. `tftVersusHandler.js` also builds all image URLs (champions, items, augments from MetaTFT's CDN by lowercased apiName; traits and ranked icons from CommunityDragon).
- **Lobby UI (scout sheet):** `#players` is `display: contents` inside the sticky `.matrix-head` grid, so each `.item.player` (`players.js`) is a column header (avatar from the live game's `profileIconId`, name, rank, edit/duel actions); Double Up `.team-container`s span two columns. Each `.item.compo` row (`dataLoader.js`) is a grid with the comp cell (carries with their build, core items ringed, 3★ targets starred), and 8 `.link-cell`s (click links the column's player, handled by delegation in `matrix.js`). `matrix.js` sets each row's `data-state` (`open` = uncontested, shown as a star before the name / `shared` = a carry is taken by another player / `linked` / `crowded` = 2+ players) and the "Contested carries" card, which stays right under the item picker in the side panel. `compSearchBar.js` owns row visibility in one place (`applyCompVisibility()`: tags OR, comp-name text while no tag is set, the All/Uncontested/Linked view; linked comps always stay visible) and tier header counts. `itemPicker.js` is the side panel: up to 3 distinct components (recipes they complete together weigh 1, half-covered recipes 0.35) plus toggled items/artifacts/emblems, which are also draggable onto players; it lists suggested comps, shows matched items on rows and fades the rest. `compFit.js` is the shared fit rule used for every suggestion: item → a carry builds it (1) or rates it Core/S/A (1/0.8/0.5); artifact / emblem / radiant → TFT Flow's curated `conditions` for that item (tier weight S 1 … D 0.25, holder from the snapshot; comps it doesn't list don't want it), with the old heuristics only for items no list covers. `playerItems.js` owns each player's box of up to 6 items (`data-items` on the player element; drop from the picker, drag between players, click to remove): it marks the player's top 3 unlinked potential comps as `.hint` cells, fills the "Potential comps" card (with each item's holder) for the last player touched, and badges artifact/emblem holders on the comps the player is linked to (repainted on `tft:linkschange`). `components.js` builds the duel modal (largest file); `searchCurrentGame.js` runs search → summary → live game → populates players.
- **Share URLs** (`shareUrl.js`): state is serialized into query params — `Player1..8`, `Player{N}Comps` (comp indexes) and `Player{N}Items` (item apiNames), both set-specific and cleared when the set changes, `set`, `mode` (only `mode=double` is written; absent means solo). `applyQueryParams()` runs before data loads; `linkPlayersToCompsFromQuery()` re-links after comps render.
- **Solo/Doubles mode:** the hidden `#color_mode` checkbox stays the source of truth (share URLs and live-game search set it); `toggleDoubleUpMode()` flips `body.double-up`, syncs the header switch and rebuilds the player columns.
- **Views:** `index.html` has a tab bar (`#view-tabs`) in the app header switching `#tracker-view` (the lobby) and `#transitions-view` (shown as "Set Summary"). `viewTabs.js` owns switching, keeps the view in the URL hash (`#summary`) and lazy-imports `transitionsView.js` on first open.
- **Transitions view** (`transitionsView.js`, `css/transitions.css`, classes prefixed `tv-`): early→late champion transitions by shared S/A ("ideal") items. It is built from the selected set's `champions`/`recipes`/`components` in MetaSnapshot (no data of its own) and derives AD/AP/Hybrid and tank item classes from who rates each item S/A. Entries are keyed by name, or `name|AD` / `name|AP` for `Adaptor` champions, which get one entry per build (from `variants`, or their tiers split by item class on older snapshots) and an AD/AP switch in the drawer. It reads `links` to mark champions taken by lobby players, and its drawer calls `addCompFilter()` (`compSearchBar.js`) to jump to the tracker filtered by a champion.
- **CSS** is aggregated by `css/main.css`: `variables.css` (light "scout sheet" tokens; the only color is game meaning: unit cost `--c1..5`, tiers `--t-*`, player colors, open/shared/contested states; legacy token names are mapped for the set summary view, and `#popupOverlay` restores the old dark palette so the duel modal is unchanged), `base.css`, `shared.css` (spinner, mini rank, duel button, modal rank cards, toast), `modal.css`, `match-history.css`, `lobby.css` (header, sheet, matrix, side panel, breakpoints at 1180/900/640px) and `transitions.css`. Player colors (`CONFIG.colors`) and tier colors are picked to read on white.

## Data updates

`Data/MetaSnapshot.json` is regenerated by a bot (`Zeroclbot`, commit messages like "Update MetaSnapshot (TFT Flow comps, MetaTFT items) for sets: 18") and accounts for most commits. The generator lives in the TFT Versus backend repo (`TFT_Versus`: `api/duel/scrapping/build_set_snapshot.py` combining `get_comps_tftflow.py` (scrapes the `data-*` attributes of TFT Flow's WordPress comp posts, home tier list and `/conditions/set<N>` page), `get_set_data_cdragon.py` and `get_unit_items_metatft.py`; `api/controllers/update_comps_controller.py` publishes, keeping a set's published data when a source fails), which runs on autopilot: the server detects the live set (MetaTFT) and a PBE set (TFT Flow comps for live+1) on startup and every 6h, and checks hourly whether to publish (`AUTOPILOT_UPDATES=false` disables that locally; `GET /api/update_comps?force=true` publishes now). It publishes at most every 12h, or 24h after the last publish when MetaTFT reports a new patch. No set number needs editing when a set launches. Item tiers use a placement-delta score calibrated against MetaTFT's own tiers, a rule that keeps popular items (>= 15% of the unit's item slots) at least A, and a Core tier above S for items in >= 25% of its item slots that don't clearly underperform (never Thief's Gloves, nor Gargoyle/Warmog on tanks). Every threshold is a share of the unit's item slots, never a game count (counts grow as a patch ages). Constants are in `constants/scrapping_constants.py`; the frontend shows Core as an outlined gold badge and a gold ring on item icons. Treat the file as generated and avoid hand-editing or reformatting it; keep new fields additive, since the bot also publishes to `main` where the older frontend reads it. `riot.txt` is the Riot API domain-verification file; leave it in place.
