# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

TFT Comp Tracker: a static, no-build web app for Teamfight Tactics. The user looks up a live game (or types player names), then links each of the 8 players to the meta compositions they appear to be playing, drawing Bezier lines between player cards and comp cards on a canvas. There is no package.json, bundler, linter, or test suite.

## Running

Serve the repo root over HTTP (ES modules and `fetch('Data/MetaSnapshot.json')` don't work from `file://`), e.g. `python -m http.server 8000` and open `http://localhost:8000`. `index.html` uses absolute `/favicon.ico`, so the root must be the site root.

## Architecture

- **Entry points** (both `type="module"` in `index.html`): `Scripts/mainScreen/domContentLoad.js` (DOMContentLoaded wiring: server selector, search button, tooltips) and `Scripts/mainScreen.js` (startup: `applyQueryParams()` → `tryLoadDefaultData()`, canvas resize observers, comp filter toggles, and exposing `toggleDoubleUpMode`/`resetPlayers` on `window` for the inline `onchange`/`onclick` handlers in `index.html`).
- **Modules query the DOM at import time** (e.g. `document.getElementById('players')` in `players.js`, `'lineCanvas'` in `canvas.js`, `'compos'` in `dataLoader.js`), so they rely on `index.html` script placement and there are circular imports between `players.js`, `canvas.js`, `dataLoader.js`, `compSearchBar.js` and `shareUrl.js`. Be careful when moving code between these files.
- **Shared state** lives in module-level exports rather than a store: `links` (player↔comp pairs, in `canvas.js`) is the source of truth for the drawn lines and share URLs; `duelsCache` in `players.js`; `metaSnapshotData`, `unitImageMap`, `unitCostMap`, `items` in `dataLoader.js`.
- **Two data sources:**
  1. `Data/MetaSnapshot.json` — one entry per set, keyed by set name (`"SET 18"`): `comps` (TFT Academy tier list; each carry's `items` are its ideal build from MetaTFT), `champions` (every 1-5 cost unit with TFT Academy `role` like "Attack Fighter", `traits`, `stats`, and `items: {base, games, core, S, A}` rows `[itemApiName, avgPlacement, games]` from MetaTFT live data, plus `artifacts` in the same shape, tiered only against the unit's other artifacts; champions with an `Adaptor`-style trait also get `variants: {AD, AP}` tiers, each from its damage class's items (TFT Academy item tags) plus hybrid ones; comp carries get `artifacts` too, and `variant` when TFT Academy's build picks one), `items` (catalog by category), `components`, `recipes`, `patch` (MetaTFT patch, or "PBE"), `status` (`live`/`pbe`), `source`/`itemsSource`, `lastUpdated`. A set on the PBE (about two weeks before launch) is published next to the live one with stand-in tiers from TFT Academy builds (`avg` null, `games` = number of builds). Loaded by `dataLoader.js`, cached in `sessionStorage` under a versioned key (`metaSnapshot:v3`; bump it when the format changes, and hard-reload/new tab after changing the file). The live set is the default (older frontends use the last key, so the backend writes the live set last); the set dropdown is built from the keys, labels PBE sets and is hidden when there is only one set, and `getCurrentSetData()` plus the `tft:setchange` document event expose the selected set to other views.
  2. The external **TFT Versus** backend (`https://tft-versus.onrender.com/api`, endpoints in `Scripts/config.js`), called only through `fetchFromTFTVersusAPI` in `Scripts/tftVersusHandler.js`. Errors come back as `{detail, status}` (real HTTP status attached); callers such as `searchCurrentGame.js` check `detail`/`status` rather than catching. `tftVersusHandler.js` also builds all image URLs (champions/items/augments/traits/ranked icons from MetaTFT, TFT Academy, CommunityDragon).
- **UI structure:** `components.js` builds the player cards and the duel modal (largest file). `compSearchBar.js` handles comp filtering (champ/item/style text search plus the hide-contested / hide-unselected toggles via `createCompToggle`). `searchCurrentGame.js` runs search → summary → live game → populates players.
- **Share URLs** (`shareUrl.js`): state is serialized into query params — `Player1..8`, `Player{N}Comps` (comp indexes, set-specific, so cleared when the set changes), `set`, `mode` (only `mode=double` is written; absent means solo). `applyQueryParams()` runs before data loads; `linkPlayersToCompsFromQuery()` re-links after comps render.
- **Solo/Doubles mode:** toggled via `body.double-up` class; player cards are wrapped in team containers with team icons (`players.js`).
- **Views:** `index.html` has a tab bar (`#view-tabs`) switching `#tracker-view` (the original left/canvas/right layout) and `#transitions-view` (shown as "Set Summary"). `viewTabs.js` owns switching, keeps the view in the URL hash (`#summary`), resizes the canvas when the tracker is shown again (it is 0×0 while hidden), and lazy-imports `transitionsView.js` on first open.
- **Transitions view** (`transitionsView.js`, `css/transitions.css`, classes prefixed `tv-`): early→late champion transitions by shared S/A ("ideal") items. It is built from the selected set's `champions`/`recipes`/`components` in MetaSnapshot (no data of its own) and derives AD/AP/Hybrid and tank item classes from who rates each item S/A. Entries are keyed by name, or `name|AD` / `name|AP` for `Adaptor` champions, which get one entry per build (from `variants`, or their tiers split by item class on older snapshots) and an AD/AP switch in the drawer. It reads `links` to mark champions taken by lobby players, and its drawer calls `addCompFilter()` (`compSearchBar.js`) to jump to the tracker filtered by a champion.
- **Performance helpers:** `lazyLoader.js` + `performanceOptimizer.js` (device-tier detection, image request queue, CommunityDragon image sizing) support lazy image loading.
- **CSS** is split under `css/` and aggregated by `css/main.css`; design tokens are in `css/variables.css`.

## Data updates

`Data/MetaSnapshot.json` is regenerated by a bot (`Zeroclbot`, commit messages like "Update MetaSnapshot (TFT Academy comps, MetaTFT items) for sets: 18") and accounts for most commits. The generator lives in the TFT Versus backend repo (`TFT_Versus`: `api/duel/scrapping/get_comps_tftacademy.py`, `get_unit_items_metatft.py`, `api/controllers/update_comps_controller.py`), which runs on autopilot: the server detects the live set (MetaTFT, falling back to TFT Academy) and a PBE set (TFT Academy comps for live+1) on startup and every 6h, and checks hourly whether to publish (`AUTOPILOT_UPDATES=false` disables that locally; `GET /api/update_comps?force=true` publishes now). It publishes at most every 12h, or 24h after the last publish when MetaTFT reports a new patch. No set number needs editing when a set launches. Item tiers use a placement-delta score calibrated against MetaTFT's own tiers, a rule that keeps popular items (>= 15% of the unit's item slots) at least A, and a Core tier above S for items in >= 25% of its item slots that don't clearly underperform (never Thief's Gloves, nor Gargoyle/Warmog on tanks). Every threshold is a share of the unit's item slots, never a game count (counts grow as a patch ages). Constants are in `constants/scrapping_constants.py`; the frontend shows Core as an outlined gold badge and a gold ring on item icons. Treat the file as generated and avoid hand-editing or reformatting it; keep new fields additive, since the bot also publishes to `main` where the older frontend reads it. `riot.txt` is the Riot API domain-verification file; leave it in place.
